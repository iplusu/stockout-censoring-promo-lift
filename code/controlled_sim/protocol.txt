1      Purpose, inputs, and fixed scope

This is a fully synthetic simulation. FreshRetailNet data are not an input. No new external
data need to be collected. The existing empirical study and completed simulations remain separate
evidence. Here we generate demand with known coefficients so that estimation error can be measured
directly; true demand during real stockouts is unobserved.
The experiment addresses RQ2: how does the relative accuracy of censored Poisson change when demand–
capacity dependence changes at controlled expected censoring rates? It also evaluates the combined lift
implied by promotion and discount-depth coefficients. Equal censoring rates do not guarantee equal
information or equal identification strength.

3    Random streams and observed data

Use double precision and record exact language, package, operating-system, and random-generator ver-
sions. The reference convention is NumPy Generator(PCG64(...)) initialized through SeedSequence;
another implementation must document an equivalent, reproducible stream scheme before production.
Create SeedSequence(20261122) and spawn three child sequences in this fixed order: evaluation,
bootstrap, engineering checks. From the evaluation child, spawn exactly 1,000 children and assign
child r − 1 to replicate ID r. Worker scheduling must not determine seeds. For each replicate, draw a
length-2,400 ZD array and then a length-2,400 ZC array. Retain the fixed stratum order in Section 1.
Reuse both normal arrays across all six conditions. Compute demand once per replicate; it
must be identical across its six conditions. Capacity changes through η and the calibrated mean. Each
condition contains
                                   K = min(D, C),      I = 1{D > C}.
Equality D = C is uncensored. For a censored observation, K = C and demand is strictly greater than
K. For an uncensored observation, K = D.
If floating-point normal CDF evaluation returns exactly 0 or 1, replace only that endpoint by the closest
representable number inside (0, 1) before applying the Poisson quantile. Count such adjustments. This
is a numerical boundary safeguard, not trimming of generated observations.
Estimator information sets. Give G only (X, K); give M only (X, K, I); give O (X, D). True capacity,
demand, η, and q must not enter G or M as extra regressors, starting-value truths, or selection rules.
Use X = (1, P, d) without interactions, penalties, coefficient constraints, weights, or standardization.
The truth is used to generate data, evaluate error, and fit the explicitly labeled oracle.
Record every generated dataset. Save its replicate ID, condition, realized censoring share overall
and by stratum, uncensored counts by stratum, and rank of the uncensored design matrix. Never reject,
resample, or modify a dataset to force exactly q censoring or a minimum uncensored count. Variation
around the calibrated rate is expected.

6    Validity, failures, and information diagnostics

A fit is numerically valid for accuracy summaries only when all of the following hold:
1. The finite-maximum screen passes without an unresolved numerical status.

2. At least one permitted optimization attempt reports convergence, with finite coefficients and objective
   and independently verified gradient infinity norm at most 10−6 .

3. Predicted lift at all three specified depths, the averaged lift loss, and both coefficient losses are finite.
These rules do not establish well-conditioned or strongly identified estimation. Keep information
diagnostics separate from accuracy eligibility. Do not exclude a large but finite loss, a coefficient sign
reversal, or a high condition number merely because it looks implausible.
Store separate Boolean flags for structural nonexistence, unresolved structural screen, optimizer non-
convergence, nonfinite objective/coefficient, and nonfinite lift/loss. Also assign one mutually exclusive
final status, in that priority order, ending with valid. When reporting a total failure count, count each
attempted model fit once. Starts are not independent replicate attempts.
Joint subsets. For each condition, define Vηq as replicate IDs where both M and G are valid. Use this
same set for all three paired contrasts in Table 6. For the dependence contrast at q, use Wq = V0q ∩ V0.6,q .
Oracle validity is recorded separately and never determines eligibility for an M − G comparison. Failed
fits receive missing losses, not zeros, capped losses, oracle replacements, or newly generated datasets.
Observed information. At a finite converged M candidate, the Hessian of the average negative log

8    Monte Carlo uncertainty and required tables

Use the bootstrap child stream to draw 2,000 length-1,000 vectors of replicate IDs with replacement. Use
the same resampled ID vector for every condition, estimator, and statistic in a bootstrap
iteration. Carry each sampled ID’s validity flags with it, and retain repeated IDs with their multiplicities.
This preserves the common-random-number pairing across conditions.
Within each resample, reconstruct Vηq and Wq and recompute the statistics as defined in Section 7. Do
not bootstrap rows within a simulated dataset, sample models independently, or resample empirical
cities. For each statistic, report the original point estimate, the 2.5th and 97.5th percentiles of its
bootstrap estimates, and their sample standard deviation (denominator Busable − 1) as its Monte Carlo
standard error. Use the ordinary midpoint median for even sample sizes and linear-interpolated quantiles
consistently; record the convention in the software manifest.
If a bootstrap resample contains no eligible pairs, record that statistic as missing for that iteration.
Report Busable out of 2,000 for every statistic. Never draw extra resamples to replace an empty one. If
fewer than two estimates are usable, its interval and standard error are unavailable. If some estimates
are missing, clearly identify the resulting interval as based on the estimable resamples; do not silently
describe it as a complete 2,000-resample interval. A statistic with no original valid pairs is not estimable.

are pointwise; no multiplicity-adjusted confirmatory family or unrequested      significance tests are added.

9    Validation, execution order, and stopping rule

Complete engineering checks before opening aggregate production performance results. Use deterministic
unit-test examples and the separate engineering stream, with a fixed five smoke-test replicate IDs across
all six conditions. These 30 datasets test implementation only and are excluded from the 6,000 evaluation
datasets. Their estimator ranking is not a pass/fail criterion.

1. Censoring checks. Hand-check (D, C) = (2, 2), (3, 2), (1, 2): they must yield (K, I) =
   (2, 0), (2, 1), (1, 0). Check nonnegative integer support and that censored observations use a
   strict survival contribution.

2. Likelihood checks. With every I = 0, M ’s objective and gradient must equal ordinary Poisson on
   the same outcome. Compare strict Poisson tails against direct summation for small deterministic
   cases. Verify the objective and gradients without hidden regularization or probability floors.

3. Derivative checks. On fixed small datasets, compare analytic gradients with centered finite
   differences; require scaled maximum discrepancy below 10−5 with scale 1 + ∥g∥∞ . Check the Hessian
   against gradient differences to scale 10−4 . Also compare log-survival, score, and curvature in a
   far-right-tail case, such as K = 1000, µ = 1, against a high-precision positive-tail sum. Record
   precision, steps, and errors; moderate-only checks do not establish tail stability.

4. Structural checks. All-censored and all-zero uncensored examples must be flagged as having no
   finite maximum. Uncensored positive observations spanning the three design columns must pass.
   Test a mixed example with an uncensored zero and missing positive-outcome support; check its LP
   certificate against direct movement along that direction.

5. Calibration and streams. Check all 24 population discrepancies, the independent-demand/capacity
   identity at η = 0, identical demand across conditions within an ID, different streams across IDs, and
   identical results when a small set of IDs is scheduled in a different worker order.

6. Pairing and output checks. On hand-constructed loss arrays, verify median paired differences,
   the nested paired Θ calculation, bootstrap multiplicities, and missing-fit eligibility. Verify that a
   large finite loss is retained and failed fits remain in denominators.

Freeze the configuration, calibration file, source commit, dependency versions, validation log, and seed
mapping. Run IDs 1–1,000; retain all six conditions per ID and checkpoint by ID. A crashed job may
resume only missing tasks under the same seeds and configuration. Then create summaries and the
2,000 bootstrap iterations without any change to the design.
Finish after the fixed budget. Do not add conditions, seeds, observations, estimators, starts,
replicates, or sensitivity analyses because an effect is weak, negative, noisy, or inconsistent with the draft.
Large failure rates are reportable outcomes. If the primary contrast is not estimable or its interval is
wide, report that limitation and complete the package.
A confirmed coding or numerical defect may justify a corrected implementation and a full rerun on the
same scheduled IDs; preserve the original logs and document the defect and version change. This is
correction of an invalid computation, not additional evidence. A substantive design change requires a
separately documented amendment before a new run and must not be silently merged with this one.
